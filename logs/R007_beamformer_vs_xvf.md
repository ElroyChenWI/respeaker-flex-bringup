# R007 — 自己寫的 delay-and-sum / MVDR vs XVF3800 的處理後輸出

- 日期：2026-10-10
- 前提：XVF 跑 USB 6ch 韌體（R005）；方向用自己的 SRP-PHAT 估計（R006）

## Hypothesis

在真實房間裡，MVDR（用「只有噪音」那段算噪音的共變異矩陣）壓噪音的效果會明顯比 delay-and-sum 好，而且至少能接近 XVF 的處理後輸出。

## 動作

1. `host/algo/beamformer.py`：STFT（512 點、sqrt-Hann、50% 重疊）
   - delay-and-sum：`w = d/M`
   - MVDR：`w = R⁻¹d / (dᴴR⁻¹d)`，對角加載 1%
2. 合成測試（`algo/test_algo.py`）：
   - STFT 往返誤差 1.3e-15
   - MVDR 對目標方向的響應 = 1.000（不失真）
   - 目標 90°、等功率干擾在 0° / 180° / 45° → MVDR 的 SIR 增益 **+32.0 / +32.0 / +23.6 dB**；delay-and-sum 只有 +4.9 / +4.9 / +2.2 dB
3. 實際錄音 `captures/doa_20261010_182453_truebeam.wav`（本機檔，20 秒 6ch）：
   - 手機放音樂當干擾，使用者在另一側講話
   - 實際順序：**0–13 s 講話 + 音樂，14–19.7 s 只有音樂**（跟原本的預設相反）
   - `beam_eval.py` 加了 `--noise START END` 和 `--speech START END` 參數
4. 指標：推估 SNR = (P講話段 − P噪音段) / P噪音段，對 5 種輸出各算一次

## 觀察

**方向**
- 干擾（只有音樂那段）：SRP 約 **196°**，逐秒穩定在 195–208°
- 講話者：三方一致
  - XVF `DOA_VALUE` 87°（講話段 358/391 幀判定為人聲，338 幀落在 90°）
  - 自己的 SRP（最大聲 30% 幀）91°
  - 「講話段 SRP 圖 − 噪音段 SRP 圖」的峰值在 83°

**SNR（噪音 14.3–19.5 s，講話 1.0–13.5 s）**

| 輸出 | 推估 SNR | 比單支麥克風 |
|---|---|---|
| mic0（原始） | 6.9 dB | 0 |
| delay-and-sum | 7.1 dB | +0.2 dB |
| **MVDR**（目標 83°） | 11.6 dB | **+4.7 dB** |
| MVDR（目標固定 90°） | 11.7 dB | +4.9 dB |
| **XVF ch1**（處理後） | 21.8 dB | **+14.9 dB** |
| XVF ch2（ASR beam） | 8.2 dB | +1.4 dB |

- MVDR 對干擾方向和目標方向的響應差（300–3800 Hz）：**−16.7 dB**
- 目標方向 83° 或 90°，結果幾乎一樣 → 方向估計不是瓶頸

## 結論

- **實測中，MVDR 只比單支麥克風好 +4.9 dB，遠低於合成的 +32 dB；XVF ch1 好 +14.9 dB，這一局 XVF 明顯贏**
- 差距的可能原因：
  - **回音**：手機的聲音被牆壁和桌面反射，從多個方向進來；只有 4 支麥克風、4.4 cm 的陣列，只能挖幾個空間零點
  - 手機不是理想的點聲源；陣列小，低頻幾乎沒有指向性
  - **XVF ch1 不只做空間濾波**：還有後處理的降噪和 AGC。只做 beamforming 的 XVF ch2 是 +1.4 dB，比較接近「只靠空間濾波」能做到的程度
- 這個指標假設噪音是穩態的，但音樂不是；XVF 的 AGC 在兩段之間也可能用了不同增益，所以 XVF 的數字只能當參考，**要搭配用耳朵聽**（每種輸出都有存 `_mic0` / `_das` / `_mvdr` / `_xvf_ch1` / `_xvf_ch2` 的 WAV）
- 下一步（一次只改一件事）：在 MVDR 後面加單聲道 Wiener 後處理濾波（multichannel Wiener filter），把「空間濾波 + 頻譜降噪」組合起來，跟 XVF ch1 比
